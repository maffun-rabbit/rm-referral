# ガイド・トピックページ制作レギュレーション v1

## 適用範囲

今後 `topics/` 配下へ新しく追加する検索意図別の記事に必ず適用する。`guide/` は制度・手順を体系的に説明するガイド、`topics/` は個別の疑問に答える記事として役割を分ける。公開済みページは、明示的な移行依頼がない限り変更しない。トップ、ショップ、都道府県ページは、それぞれ別の専用設計を持ってよい。

## 制作コマンド

```bash
npm run page:new-topic -- ja example-topic
```

生成された `content/pages/{locale}/topics/{slug}/page.json` だけを編集する。完成HTML、独自ヘッダー、独自フッター、ページ固有CSS・JSを追加してはならない。

## 常に固定する部分

文章やリンク先が変わっても、UI、並び順、記事幅、余白、レスポンシブ動作を変更しない。

1. 共通ヘッダーとフッター
2. パンくず：トップ → トピック一覧（`/topics/`） → 現在ページ
3. 最大1116pxの記事幅と左右の安全余白
4. ヒーロー：アイブロウ、H1、結論リード、本文ジャンプ、出典ジャンプ、3点要約
5. 出典パネル：説明、公式リンク、情報確認日
6. CTA：アイブロウ、見出し、説明、主要リンク、必要な開示文
7. 関連ページ：見出し、カードUI、遷移ラベル
8. 見出し階層、文字サイズ、行間、フォーカス、モバイル1カラム化

リンク先とリンク文言はページごとに独自化してよい。外国語の内部リンクは同じ言語へ向け、日本語へフォールバックさせない。

## 内容に応じて可変にできる部分

本文セクションの個数、順序、文章、画像、項目数は変えてよい。ただし承認済みの型だけを使う。

| type | 用途 | 制約 |
| --- | --- | --- |
| `prose` | 結論・背景説明 | 1つ以上の段落 |
| `steps` | 手順・時系列 | 各項目に見出しと説明 |
| `comparison` | 2案の比較 | 2列固定 |
| `cards` | 注意点・特徴 | 各カードに見出しと説明 |
| `warning` | 重要な注意 | ラベルと本文が必須 |
| `faq` | よくある質問 | 質問と回答の組 |
| `table` | 条件・料金比較 | 列数とセル数を一致 |
| `media` | 画像・画面解説 | `src`と意味のある`alt`が必須 |

新しい表現が必要な場合は、ページ固有HTMLやCSSで回避せず、共通セクション型として実装・検証してから使う。

## 情報設計

- H1は1つ。本文セクションはH2、カード内はH3とし、階層を飛ばさない。
- ヒーローのリードで検索意図への回答を一文で先出しする。
- 3点要約を必須とし、詳細を読まなくても重要事項が分かる表現にする。
- 1セクション1論点を原則とする。
- 料金、条件、期間、制度は出典と確認日を付ける。
- CTAは本文と関係する次の行動だけにし、クリック後に起きることを説明する。
- 関連ページは最低1件とし、自分自身へはリンクしない。

## デザイン基準

- 本文16〜17px相当、行高1.6〜1.75。
- 文字階層は本文、H3、H2、H1の4段階以内。
- 余白は8pxを基礎単位として16、24、32、48、64、80、96pxを中心に使う。
- PCの記事最大幅1116px、文章部分760px程度。
- 760px以下は1カラム。表だけ横スクロールを許可する。
- 色だけに意味を依存せず、ラベル、見出し、記号を併用する。
- リンクとボタンはキーボードフォーカスを視認可能にする。

## 完了条件

1. `npm run test:shared`
2. `npm run build`
3. `npm run verify:release`
4. PC・モバイルで固定領域と使用した全セクションを確認
5. title、description、canonical、構造化データ、同一言語リンク、外部リンクを確認
6. 公式情報の確認日と参照URLを記録

検証を迂回したページは公開しない。
